## 14. 診断上の制約
- グレーボックス・LLM支援；認証は「できなければ停止」（`authentication.enabled` 時、任意アプリでの
  認証成功は保証しない）；キーなしZAPはローカル限定；Active Scanはゲート付き。
- **破壊的検証**：`scan.destructive`＝<有効 / 無効>。有効時は対象アプリ内部の不可逆な状態変更まで
  実施（使い捨てローカル対象前提）。外部への副作用（外部メール/課金/外部SSRF等）は実施していない。
- **可用性への影響**：`scan.availability_impact`＝<有効 / 無効>。無効時はDoS相当の検証なし。
- **認証アカウント構成**（該当時）：<単一 / 同一ロール2 / 異ロール / 3>。実施できた認可クラスと
  できなかったクラスは 5〜7・`authentication.md` を参照。

## 15. 免責事項
許可されたホストのみを診断しました。結果には誤検知/検知漏れが含まれ得るため、対応前に人間の確認を
要します。本診断は**自分が所有する使い捨てのローカル脆弱アプリ**を対象とし、`scan.destructive`
有効時は対象内部を不可逆に変更する検証を含みます（何を変更したかは本文に記録）。サンドボックスの外
（外部サービス・実在インフラ）への副作用は行っていません。
