## 2. SAST 指摘の根拠（`sast.enabled: true` のときのみ）

> 指摘IDごとに1ブロック。**仮説・根拠・file:line・深刻度・SAST が既に否定したか**を書く。
> **再現手順の操作列・直し方・CVSS・追加テストケースは転記しない**（`references/safety-policy.md`
> ルール11＝SAST 由来は仮説と根拠にしかならない）。**ペイロードの実例は根拠として残してよい**。

### F-01 — <ログイン欄と検索欄からの SQL インジェクション>

- 深刻度 `[H]`：Critical（SAST の集計節より）
- 仮説：ログインの認証条件をユーザー入力で常に真にでき、パスワードを知らずにログインできる
- 根拠 `[H]`：`routes/login.ts:34` — クエリにユーザー入力を**テンプレート文字列で連結**している。
  説明中のペイロード例：`' OR 1=1;--`
- 期待される安全な挙動：401 が返り、応答にユーザーのハッシュ等が現れない
- SAST の判定：問題あり（否定されていない）
- 突合先：エンドポイント表 #1（突合方法：シンク一覧の到達経路経由）

### Q-01 — <トークン署名検証関数の呼び出しが正しいか（静的に解けない）>

- 深刻度 `[H]`：要確認
- 仮説：検証関数が誤った引数で呼ばれており、検証が素通りする可能性がある
- 根拠 `[H]`：`lib/insecurity.ts:55` — 依存ライブラリの実体が `.gitignore` 済みで読めず、
  **SAST を何回回しても確定しない**。ロール判定・2FA・現在ユーザー取得が全てこの関数に依存
- 期待される安全な挙動：無効なトークンで 401
- 突合先：エンドポイント表 #2 ほか（要認証の全エントリに波及）
- **DAST が優先的に決着させる項目**：有効・無効なトークンを1回ずつ送れば確定する

## 補足

- `[I]` の項目は推測であり、事実として報告する前に動的に確認する必要がある。
- `[H]` の項目は**伝聞**であり、DAST 自身は確認していない。再現できたら「HTTPで確認できた事実」へ
  昇格させ、再現できなければ「再現できなかった」で終端する（**「誤検知の可能性」に落とさない**）。
- 除外（診断しない）：<exclude.paths の内容>。
